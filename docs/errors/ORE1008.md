# ORE1008

> Invalid regular expression: ….

Group: [Syntax](README.md#ore1xxx-syntax) · specification: [Regular expressions](../spec/02-types.md#regular-expressions)

## What it means

A regular expression literal is compiled when the program is compiled, so an
invalid pattern is a compile-time error rather than a `SyntaxError` at run
time. The message gives the reason: an unterminated group or class, a bad
quantifier, a flag that is not supported. Ore supports JavaScript's syntax
without the `u` flag; lookbehind and the flags `u`, `v` and `d` are rejected
for now.

## Example

```ts
const re = /a(/
```

## How to fix

Correct the pattern. A literal parenthesis, bracket or other special
character is escaped with `\`:

```ts
const group = /a()/
const paren = /a\(/
```

A lookbehind can often be replaced by a group and the text of that group:

```ts
const price = /\$(\d+)/
const m = price.exec("costs $25")
if (m !== null) console.log(m.at(1)!)
```
