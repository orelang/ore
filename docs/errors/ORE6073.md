# ORE6073

> Module '…' has already exported a member named '…'. Consider explicitly re-exporting to resolve the ambiguity.

Group: [Declarations, functions, generics, modules and C](README.md#ore6xxx-declarations-functions-generics-modules-and-c) · specification: [Modules and packages](../spec/07-modules.md#modules-and-packages)

## What it means

Two `export *` of a module re-export the same name from different
declarations, so the name is ambiguous and the module does not export it.
The error is at the later `export *`, as in TypeScript. A name that both
modules re-export from the same declaration is not ambiguous, and a name
the module exports itself takes precedence over `export *`.

## Example

```ts
export * from "./circle"
export * from "./square"
// file: circle.ore
export function area(r: f64): f64 {
    return 3.14159 * r * r
}
// file: square.ore
export function area(side: f64): f64 {
    return side * side
}
```

## How to fix

Re-export the name explicitly, choosing one, or under two names:

```ts
export * from "./circle"
export * from "./square"
export { area } from "./circle"
export { area as squareArea } from "./square"
// file: circle.ore
export function area(r: f64): f64 {
    return 3.14159 * r * r
}
// file: square.ore
export function area(side: f64): f64 {
    return side * side
}
```
