# ORE6043

> Function '…' must return a value of type '…' on every path.

Group: [Declarations, functions, generics, modules and C](README.md#ore6xxx-declarations-functions-generics-modules-and-c) · specification: [Statements](../spec/04-functions.md#statements)

## What it means

A function with a return type must return a value on every path that
reaches the end of its body; Ore has no `undefined` to return implicitly. A
path that ends in an infinite loop or a call that never returns, such as
`process.panic(...)`, needs no `return`, and neither does an exhaustive
`switch` over a union of string literals.

## Example

```ts
function sign(x: int): int {
    if (x > 0) return 1
    if (x < 0) return -1
}
```

## How to fix

Return a value at the end too:

```ts
function sign(x: int): int {
    if (x > 0) return 1
    if (x < 0) return -1
    return 0
}
```

If the end cannot be reached, say so with a panic:

```ts
function sign(x: int): int {
    if (x >= 0) return 1
    if (x < 0) return -1
    process.panic("unreachable")
}
```
