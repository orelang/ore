# ORE6079

> A generator function needs a return type annotation, such as 'Generator<T>': ….

Group: [Declarations, functions, generics, modules and C](README.md#ore6xxx-declarations-functions-generics-modules-and-c) · specification: [Generators and iteration](../spec/04-functions.md#generators-and-iteration)

## What it means

Without an annotation, a generator function's type comes from its body:
`Generator<T, TReturn, null>`, with T the types of the values it yields.
Ore cannot take it from the body when the type is needed before the body is
checked:

- the generator is used in its own body, such as a recursive `yield*`;
- it is a nested function declaration, which is hoisted: it can be called
  before its body, which sees the variables declared after it;
- it is a method of an object literal that uses `this`, whose type includes
  the method's.

## Example

```ts
type Tree = { value: int; children: Tree[] }

function* walk(tree: Tree) {
    yield tree.value
    for (const child of tree.children) yield* walk(child)
}
```

## How to fix

```ts
type Tree = { value: int; children: Tree[] }

function* walk(tree: Tree): Generator<int> {
    yield tree.value
    for (const child of tree.children) yield* walk(child)
}
```
